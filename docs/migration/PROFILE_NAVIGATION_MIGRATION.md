# Profile privacy and navigation synchronization — 5 November 2026

Scope: OVU only, new Supabase project `pdvwkdggyyrfkoqrpbji`. No Store, production, payment-provider, customer-access or deployment change.

Migration 0011 is installed. A restrictive owner-only SELECT policy prevents a public student profile from exposing raw guardian contact/preferences fields. Privacy-aware public certificate verification and explicitly shared exports continue through the backend. Navigation table writes and its new transaction are denied to browser roles. The backend authenticates the request, checks the optional expected account before writes, and supplies its own user ID to the service-only RPC.

`academy_sync_navigation` uses the same learner lock as official assessment/completion/certificate transactions. It preserves canonical verified completion, its date and 100% status. Other navigation can increase reading percentage/time but cannot grant verified completion, badges, certificates or paid access. A malformed batch rolls back navigation and level updates together. Overlong/noncanonical module IDs cannot be truncated into valid IDs. No migration backfill occurs.

The login hook reads only the signed-in account's scoped cache. Guest and unowned legacy navigation are not assigned to the next account. Auth callbacks defer API work until the auth lock releases; request generations and response identity checks discard stale profile responses. Profile initialization retries unique-key races and returns only committed public IDs. Storage failure reports pending synchronization instead of fabricating a persisted student identity. Authenticated update failure cannot fall through into guest persistence.

The editor now mounts from the current profile when opened and remounts if its owner/public identity changes. This fixes an observed browser bug where the dashboard showed the persisted account but the continuously mounted editor retained guest defaults. Saving is disabled while an authenticated profile identity remains pending. Existing child privacy rules use the stored age/consent/visibility when an update omits those fields. Configured guardian consent remains self-reported application state; no guardian identity-verification system is claimed.
