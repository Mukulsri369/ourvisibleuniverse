# End-to-end audit — 28 October 2026

## Scope and outcome

Tested the production build's public pages and signed-out guards, plus the real StarsApp component in an isolated browser fixture. The fixture exposes state for assertions; it does not change the production authentication or access checks.

The public sweep recorded **497 successful button clicks across 27 route visits**, including a second pass over interactive public tools. These are recorded interactions, not a claim that every possible combination of application state has been exhausted.

## Fixes made

- Replaced the broken local `vite preview` command. It requested `dist/server/server.js`, while the Lovable/Nitro build produces `.output/server/index.mjs`. The new Node preview adapter serves the actual Cloudflare fetch entry and built assets, preserves response headers/cookies, supports HEAD requests, and rejects static-asset writes.
- Opening navigation settings now minimizes the explorer map, so the map cannot intercept clicks on the settings controls.
- Connected the orphaned Cosmic Scale Journey toolbar action to the mounted guided-tour tab.
- Made the auto-orbit button subscribe to its actual state and expose its pressed state immediately.
- Added accessible names to dialog close buttons and general navigation sliders; updated the guide for galaxy-first exploration.
- Preserved the validated local destination when protected pages redirect to sign-in. A valid checkout plan now survives the redirect.
- Required explicit galaxy exit before a large-scale tour starts. A pending tour/stage resumes after exit, and entering a galaxy stops the competing tour.
- Removed duplicated geodesic call sites from the black-hole fragment shader. The dynamic loop retains exactly the same native-resolution rays and critical-curve supersampling.

Updated two older validation scripts whose fixtures/source assertions still expected pre-galaxy-scope navigation and older rendering implementation details. The 350 ms cosmic-web benchmark threshold was not relaxed; its loaded-machine failure passed on an isolated rerun.

## Automated coverage

The 57 existing validation suites passed after isolated reruns and the stale assertions/fixture corrections. These include astronomy/catalogues, the academy's 24 modules, assessments, achievements, certificates, payment-access administration security in an isolated SQL database, navigation, galaxy lifecycle, nebulae, compact objects, audio and rendering.

Added:

- `npm run test:preview`: starts the actual built preview and checks public routes, stylesheet MIME types, HEAD, missing assets and rejected asset writes.
- `npm run test:exploration-camera`: checks exit requirements, pending scale stages, visible tour controls and release of competing camera ownership.

Final changed-code checks: **TypeScript, changed-code ESLint, the final Lovable-target production build and all six final targeted regression suites passed**.

## Black-hole GPU comparison

Device: Intel Iris Xe via ANGLE / Direct3D11. Comparison used a 96×96 floating-point render target, deterministic background/noise and the same uniforms before and after the shader edit.

| Case | Maximum pixel difference | Baseline draw + readback | Optimized draw + readback |
| --- | ---: | ---: | ---: |
| Sagittarius A*, 32 Rₛ | 0 | 38,437.6 ms | 9,526.9 ms |
| Sagittarius A*, 8 Rₛ | 0 | 51.5 ms | 21.3 ms |
| Sagittarius A*, 3.2 Rₛ / falling | 0 | 36.6 ms | 22.8 ms |
| Sagittarius A*, 1.08 Rₛ / falling | 0 | 23.6 ms | 20.2 ms |
| Dormant Gaia BH1, 12 Rₛ | 0 | 35.3 ms | 21.5 ms |

The first draw includes shader compilation and setup. This microbenchmark is not a production FPS claim. The subsequent complete 960×640 descent passed where the earlier larger-viewport run stalled. Image resolution, integration settings, star counts, descent path and the number of antialiasing rays were unchanged.

## Lovable and external-service boundaries

- The production build command, Cloudflare target, GitHub branch and Lovable sync configuration are unchanged.
- No environment-variable, database-schema or migration changes are required by these fixes.
- Google provider sign-in was deliberately left untested at the user's request. Its provider implementation was not changed.
- No real payments, customer subscription modifications, live admin writes, certificate issuance or external messages were performed. Transactional/security behavior was covered with isolated automated fixtures.
- The official store navigation was checked: the existing .store URL redirects successfully to the .shop site.
- A successful local build does not confirm a future hosted deployment. Lovable's deployed environment must still provide its existing secrets and service configuration.
- Changes have not been pushed as part of this audit.
